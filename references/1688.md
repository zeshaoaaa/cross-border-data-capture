# 1688 供应商数据获取流程

本流程用于 1688 搜索结果、商品详情页、供应商旺铺、公司档案、价格、起批量、SKU、库存、包装尺寸、重量、跨境属性和店铺服务指标采集。

本流程来自 2026-05-08 的实际页面观察：

- 1688 首页未必直接登录墙；部分浏览器打开首页会跳淘宝登录，真实登录态更稳定。
- 正确搜索入口不是手写 `keywords=<关键词>` 搜索 URL，而是先打开 1688 首页或搜索页，再把关键词输入搜索框并点击“搜索”。页面表单会自行生成实际搜索结果 URL。
- 搜索表单常见 `accept-charset="GBK"`，实测最终 URL 可能把中文关键词编码成 GBK 百分号形式，例如 `keywords=%B3%E8%CE%EF...`。不要假设 `charset=utf8&keywords=<urlencoded_keyword>` 一定等价。
- 直接拼出的搜索 URL 只能作为已知结果页复查或诊断辅助，不作为标准采集入口；尤其不要用固定的 `n=y&netType=1%2C11` 这类参数模板代替真实页面搜索。
- 搜索页会给出 `找货源`、`找工厂`、`找供应商`、`找代发` 等入口。
- 搜索结果里常见商品链接是 `detail.m.1688.com/page/index.html?offerId=...`，打开后可能跳到 PC 详情页 `https://detail.1688.com/offer/<offerId>.html?...&forcePC=...`。
- 详情页页面内通常存在 `window.context.result.data`，里面有商品、价格、SKU、图集、包装、店铺等结构化数据；但仍要和可见页面交叉核对。
- 直接访问某些 `detail.1688.com/offer/<id>.html` 可能触发 `_____tmd_____/punish` 验证码拦截；遇到这种情况要标记 `blocked_by_captcha` 或 `blocked_by_browser_challenge`。
- 旺铺公司档案常见 URL：`https://<shop>.1688.com/page/creditdetail.html`。

## 适用任务

- 1688 搜索某类产品。
- 找 3-5 个候选供应商。
- 打开指定 1688 商品链接，获取商品和供应商数据。
- 获取公司档案、经营模式、交易记录、店铺服务分、回头率、粉丝数、主营、地址。
- 获取价格、起批量、SKU、库存、包装尺寸、重量、发货地、运费、保障服务。
- 判断是否跨境出口专供、主要下游平台、主要销售地区、自有品牌、IP 授权、专利货源等字段。

## 成功标准

1. 使用真实浏览器打开 1688 页面。
2. 先判断是否登录墙、验证码、淘宝登录页、`_____tmd_____/punish` 风控页。
3. 搜索页至少提取 3-5 个候选商品/供应商，除非被阻塞。
4. 每个候选至少打开详情页或旺铺页之一；只打开搜索结果不算 verified evidence。
5. 详情页提取商品字段、价格字段、SKU 字段、包装字段、供应商字段。
6. 必须下载商品详情中的图片和视频：主图、图集、详情描述长图、详情区视频、主图视频都要尽量保存到本地；如果页面没有视频或被阻塞，要写明 `not_visible` / `missing_evidence` / `blocked_by_*`。
7. 公司档案页提取经营模式、店铺服务、交易记录、信用等级、地址等字段。
8. 输出 Markdown 汇总 + CSV/JSON 结构化文件，并在 Markdown 中引用本地图片/视频相对路径。

## 安全边界

只采集交易前公开/半公开页面。

不要访问：

- 我的订单。
- 采购车。
- 消息。
- 旺旺聊天。
- 账号资料。
- 支付或下单确认页。
- 收货地址。
- 卖家后台。

不要绕过验证码或风控。遇到拦截时记录状态并停止该页面。

## 推荐工具顺序

1. `web-access`：优先使用用户已登录 Chrome。
2. Playwright headful browser：当 web-access 代理不可用但浏览器能访问 1688 时使用。
3. 普通 HTTP：只可辅助检查 URL，不要强依赖；1688 动态页面和风控经常导致 HTTP 结果不可靠。

## 采集步骤

### 1. 登录和风控检查

打开：

```text
https://www.1688.com/
```

判断：

- 如果跳到 `login.taobao.com`、`login.1688.com`，标记 `blocked_by_login`。
- 如果 URL 包含 `_____tmd_____/punish`，或标题/正文是验证码、人机验证，标记 `blocked_by_captcha`。
- 如果首页可见搜索框、订单/采购车/消息等导航，并可打开搜索页，继续。

注意：判断标准不是“看起来有没有登录”，而是“目标数据能不能拿到”。如果搜索页和详情页可读，可以继续；如果公司档案或价格字段被登录墙挡住，停止对应页面。

### 2. 用页面搜索框发起搜索

标准入口：

```text
https://www.1688.com/
```

操作顺序：

1. 在首页确认能看到搜索框，例如 `#alisearch-input` 或可访问性树里的搜索 `textbox`。
2. 清空搜索框，把关键词输入搜索框，例如 `宠物自动饮水机`。
3. 点击页面上的“搜索”按钮，或使用页面原生搜索表单提交。
4. 等新打开或跳转后的结果页加载完成。
5. 记录最终结果页 URL、页面标题、关键词、搜索入口和采集时间。

不要这样做：

```text
https://s.1688.com/selloffer/offer_search.htm?keywords=<手写编码关键词>&n=y&netType=1%2C11
https://s.1688.com/selloffer/offer_search.htm?charset=utf8&keywords=<手写编码关键词>
```

原因：

- 1688 搜索表单可能使用 GBK 编码，不一定按 UTF-8 关键词参数解释。
- 页面会附带真实搜索场景、`spm`、入口状态和登录态上下文。
- 直接手写 URL 更容易触发空结果、参数失效、页面变体不一致或风控。

搜索页要提取：

```text
keyword,result_url,result_index,title,price_text,sales_text,supplier_name,supplier_url,offer_url,service_tags,repeat_rate_text,page_status,captured_at
```

候选选择建议：

- 优先非广告或明显自然结果；如果只能看到广告，也要标记。
- 优先销量/已售可见、回头率可见、供应商名可见的结果。
- 保留完整 DOM 里的 URL，不要裁剪链接参数；1688 链接经常携带 trace、uuid、hotSaleSkuId 等上下文。
- `dj.1688.com` 广告跳转链接可记录为 `pending_evidence`，尽量打开最终详情页后再转 verified。

搜索页常见入口：

- `找货源`：商品搜索。
- `找工厂`：工厂搜索。
- `找供应商`：公司搜索。
- `找代发`：代发货源。

### 3. 打开商品详情页

搜索结果常见详情链接：

```text
http://detail.m.1688.com/page/index.html?offerId=<offerId>&...
```

打开后可能跳转到：

```text
https://detail.1688.com/offer/<offerId>.html?...&forcePC=<timestamp>
```

详情页要提取：

```text
source_url,final_url,offer_id,title,supplier_name,supplier_url,shop_age,main_business,shop_repeat_rate,shop_service_score,on_time_shipping_rate,positive_rate,price_text,min_order_quantity,sales_text,shipping_origin,shipping_to,shipping_fee_text,delivery_eta,service_tags,sku_options,sku_price_stock,product_attributes,packaging_rows,gallery_images,detail_images,detail_videos,downloaded_images,downloaded_videos,page_status,captured_at
```

### 4. 从可见页面提取

优先读取页面可见正文，例如：

- 标题。
- 价格：例如 `¥9.20`。
- 起批量：例如 `1个起批`。
- 已售：例如 `已售8.3万+个`。
- 发货地：例如 `浙江金华`。
- 运费：例如 `运费 ¥2.5 起`。
- 服务：退货包运费、晚发即赔、7天无理由退货、极速退款。
- 店铺：入驻年限、主营、店铺回头率、服务分、准时发货率、好评率。
- 商品属性：材质、品牌、产地、货号、箱装数量、是否专利货源、主要下游平台、主要销售地区、有无自有品牌、是否跨境出口专供、是否 IP 授权。
- 包装信息：长、宽、高、体积、重量。

### 5. 从页面结构化数据辅助提取

PC 详情页常见：

```js
window.context.result.data
```

可辅助读取：

- `gallery.fields.offerImgList`：商品图集。
- `description.fields.detailUrl`：详情描述资源。必须进一步打开或请求该资源，提取详情描述中的图片和视频 URL。
- `description.fields.detailVideoId`：详情区视频 ID；如果存在，要继续在页面 DOM、网络资源或 video 标签中定位可下载视频 URL。
- `mainPrice.fields`：价格、SKU 原价/优惠价、库存。
- `productPackInfo.fields.pieceWeightScale.pieceWeightScaleInfo`：SKU 包装尺寸和重量。
- `productTitle.fields.shopInfo`：供应商名、服务分、回头率等。
- `productTitle.fields.rateInfo`：评价标签、评分、好评率等。
- `shippingServices.fields` / `mainServices.fields`：保障服务。
- `sceneKey.fields.sceneList`：批发/代发场景 URL。

使用结构化数据时必须注意：

1. 它是辅助证据，不要覆盖可见页面事实。
2. 字段可能随 1688 版本变动。
3. 如果字段不可见或结构不存在，回到 DOM 文本和链接语义。
4. 不要把 `window.context` 里不懂含义的字段强行解释。

### 6. 打开供应商旺铺和公司档案

从详情页提取供应商旺铺链接，常见形态：

```text
https://<shop>.1688.com/?offerId=<offerId>&td_page_id=PC-DEFAULT-2025
```

公司档案常见入口：

```text
https://<shop>.1688.com/page/creditdetail.html
```

公司档案要提取：

```text
supplier_name,shop_url,creditdetail_url,repeat_rate,followers,main_category,established_date,buyer_protection,contact_name,phone_visible,address,consult_score,logistics_score,after_sales_score,product_score,ai_company_summary,business_model,annual_transaction_amount,oem_mode,factory_area,employee_count,sampling_capability,equipment_count,production_lines,distribution_channels,annual_new_products,rd_staff,certificates,last_30d_paid_orders,last_30d_48h_pickup_rate,last_30d_48h_fulfillment_rate,last_30d_3min_response_rate,last_30d_quality_return_rate,last_30d_dispute_rate,credit_grade,credit_rank_text,page_status,captured_at
```

注意：手机号、联系人等如果页面可见可以记录；如果不可见不要尝试绕过。

### 7. 商品详情图片和视频下载

这里是硬要求：采集 1688 商品详情时，不能只保存图片/视频 URL。只要页面能正常打开，必须尽量把商品详情中的图片和视频下载到本地。

#### 图片来源

- 商品主图。
- 商品图集。
- 商品详情描述长图。
- 详情区卖点图、规格图、场景图、包装图。
- 公司档案中的资质、环境、营业执照等图片；如果页面可见且任务需要供应商资质，也要下载。

#### 视频来源

- 主图视频。
- 详情描述视频。
- 页面 `<video>` 标签的 `src` / `currentSrc`。
- 页面脚本或结构化数据中的视频字段，例如 `detailVideoId`、`videoId`、`videoUrl`、`playUrl`、`coverUrl`。
- 如果只能拿到视频封面，下载封面并把视频标为 `video_url_not_visible`，不要伪造视频 URL。

#### 下载流程

1. 先滚动页面到详情区，触发懒加载。
2. 展开或切换到“商品详情”区域，确认详情图和视频已进入 DOM。
3. 提取 `img.currentSrc` / `img.src`，以及 `<video>`、`source`、页面脚本、`window.context.result.data` 中的视频字段。
4. 主图/图集优先保留 `cbu01.alicdn.com`、`img.alicdn.com` 中大尺寸商品图。
5. 详情长图优先从 `description.fields.detailUrl` 对应资源中提取；如果该资源需要登录或被拦，记录阻塞。
6. 过滤图标、二维码、导航小图、透明占位图、loading 图。
7. 图片下载到 `images/`，视频下载到 `videos/`。
8. 本地文件名要有业务含义，例如 `1688-offer-808854195555-gallery-01.jpg`、`1688-offer-808854195555-detail-03.jpg`、`1688-offer-808854195555-main-video-01.mp4`。
9. 每个下载文件都要在 `evidence.json` 记录：原始 URL、本地相对路径、类型、页面区域、下载状态、失败原因。
10. 如果图片或视频下载失败，不要静默跳过；在 Markdown 的“阻塞与缺失字段”里写清楚失败 URL 和原因。

#### Markdown 图片写法

Markdown 使用 figure：

```html
<figure>
  <img src="./images/1688-offer-01.jpg" alt="1688商品主图-第1张" style="max-width: 720px; width: 100%; height: auto;" />
  <figcaption>1688商品主图-第1张<br />原图 URL：https://...</figcaption>
</figure>
```

#### Markdown 视频写法

如果视频成功下载，Markdown 中同时给出本地路径和原始 URL：

```html
<figure>
  <video src="./videos/1688-offer-808854195555-main-video-01.mp4" controls style="max-width: 720px; width: 100%; height: auto;"></video>
  <figcaption>1688商品主图视频-第1个<br />本地路径：<code>./videos/1688-offer-808854195555-main-video-01.mp4</code><br />原视频 URL：https://...</figcaption>
</figure>
```

如果只拿到封面图，按图片保存，并在证据状态中写 `video_url_not_visible`。

## 风控和阻塞判断

| 现象 | 状态 | 动作 |
| --- | --- | --- |
| 跳 `login.taobao.com` / `login.1688.com` | `blocked_by_login` | 停止该页面，让用户在固定浏览器登录 |
| URL 含 `_____tmd_____/punish` | `blocked_by_captcha` | 停止该页面，不绕过 |
| 标题为验证码拦截、人机验证 | `blocked_by_captcha` | 停止该页面 |
| 搜索页能看，详情页被拦 | 搜索结果 `pending_evidence`，详情页 `blocked_by_captcha` | 不把搜索摘要当 verified |
| 公司档案打开但字段不可见 | `not_visible` / `missing_evidence` | 不猜字段 |

## 结束检查

- 搜索页候选数量是否达到用户要求；默认 3-5 个。
- 每个候选是否至少打开详情页或公司档案页。
- 是否记录完整 URL 和最终 URL。
- 是否区分搜索摘要、详情页证据、公司档案证据。
- 是否记录价格、起批量、SKU、包装、重量、跨境属性。
- 是否已下载商品主图、图集和详情描述图片到 `images/`，并在 Markdown 中使用本地相对路径。
- 是否已检查并下载主图视频、详情视频到 `videos/`；如果视频不可见、无视频或下载失败，是否写明 `not_visible` / `missing_evidence` / `video_url_not_visible` / `blocked_by_*`。
- 是否在 `evidence.json` 中记录每个媒体文件的原始 URL、本地路径、类型、页面区域、下载状态。
- 是否记录供应商服务分、回头率、近 30 天交易/履约/响应/退货/纠纷指标。
- 是否把风控页、登录页、验证码页标成阻塞。
